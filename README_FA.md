# پنل Dollax — نسخه‌ی Railway

**پورت پایتونی کامل پنل Cloudflare Worker** روی FastAPI + SQLite که برای اجرا روی
[Railway](https://railway.com) آماده است. همان پنل، همان ظاهر (سیستم تم تیره‌ی Worker)، همان کار:
مدیریت ورودی‌ها، کاربران، محدودیت حجم و سابسکریپشن — اما در چند فایل پایتونی.

> **بدون TCP Proxy.** Railway فقط یک پورت HTTPS عمومی می‌دهد؛ پس همه‌ی ورودی‌ها روی همان یک پورت با
> `wss://` و بر اساس **مسیر (path)** تفکیک می‌شوند؛ نه پورت دوم، نه `tcp_relay`.

## ۱. فایل‌ها (فقط چیزهایی که Railway لازم دارد)

| فایل | کار |
|---|---|
| `main.py` | اپ FastAPI: ورود، مسیرهای `/api/*`، سابسکریپشن، صفحه‌ی گرافیکی ساب، نقطه‌ی ورود رله |
| `db.py` | ذخیره‌سازی SQLite (ساخت جدول‌ها، مهاجرت خودکار، شمارش حجم، مدیران) — جایگزین D1 |
| `protocol.py` | ساخت لینک VLESS/VMess/Trojan/SS، کلش، سینگ‌باکس، بسته‌ی پل Xray، پارس پروتکل |
| `relay.py` | خود پروکسی: WebSocket را می‌گیرد، TCP باز می‌کند، داده را عبور می‌دهد و حجم را می‌شمارد |
| `pages.py` | صفحه‌های سمت سرور: ورود، داشبورد، **صفحه‌ی گرافیکی سابسکریپشن هر ورودی** |
| `static/style.css` | سیستم ظاهری تیره‌ی Worker (۷ تم، ساده/شیشه‌ای، پشتیبانی RTL) |
| `static/app.js` | تمام رابط: نمای کلی · ورودی‌ها · کاربران · گزارش‌ها · مدیران · تنظیمات + دوزبانه + موسیقی |
| `static/lost-soul.mp3` | موسیقی پس‌زمینه (اختیاری، برای هر مدیر جداگانه) |
| `Dockerfile` و `railway.json` | تنظیمات بیلد و دیپلوی |
| `.env.example` | همه‌ی متغیرهای محیطی |
| `requirements.txt` | وابستگی‌های اجرا |

## ۲. پنل چه کار می‌کند

### ظاهر
دقیقاً از داشبورد Worker منتقل شده: پس‌زمینه‌ی تیره با هاله‌ی رنگی، پنل‌های گرادیانی، همان ۷ تم
(**dark-green** پیش‌فرض، dark-cyan، dark-blue، green، cyan، blue، orange)، سبک **ساده/شیشه‌ای**،
فونت‌های Inter و Vazirmatn و کلید **فارسی/EN** با پشتیبانی کامل RTL.

### نمای کلی
کارت‌های آماری (ورودی‌ها، کاربران، فعال‌ها، ترافیک)، بخش **عیب‌یابی** با راه‌حل هر مورد و فید
فعالیت‌های اخیر (همراه با آی‌پی مدیر).

### ورودی‌ها — بیلدر
**ورودی‌ها → «+ افزودن ورودی»** یک بیلدر ۵ مرحله‌ای باز می‌کند، بسیار شبیه پنل Vodiwalker:

۱. **پروتکل پایه** — VLESS · VMess · Trojan · Shadowsocks
۲. **ترنسپورت** — WebSocket · XHTTP · gRPC · TCP
۳. **امنیت** — TLS · Reality · None
۴. **اندپوینت و پیشرفته** — فقط فیلدهای مرتبط: نام، آدرس، پورت، اثر انگشت، مسیر/Host، حالت XHTTP،
   سرویس gRPC، نوع هدر، Flow، SNI، ALPN، allow-insecure، fragment، کلیدهای Reality
۵. **محدودیت و چرخش** — حجم (GB)، اعتبار (روز) یا انقضای دقیق، سقف کاربر، سقف IP، سقف اتصال،
   **تعداد کانفیگ هر کاربر**، سرعت، یادداشت

نوار خلاصه و پیش‌نمایش لینک به‌صورت زنده به‌روز می‌شود. لیست هم جست‌وجو، فیلتر پروتکل، انتخاب همه،
عملیات گروهی (فعال/غیرفعال/حذف)، **ویرایش**، **کانفیگ**، **کاربران**، **بازکردن صفحه‌ی سابسکریپشن**،
**کلید جدید** (تغییر مسیر و همه‌ی UUIDها) و **حذف** دارد.

**هر ورودی بدون کاربر هم کار می‌کند.** هر ورودی اعتبار اختصاصی خودش را دارد؛ پس همان لحظه‌ی ساخت،
یک کانفیگ آماده دارید و کاربر را فقط وقتی لازم دارید که بخواهید چند نفر جدا داشته باشید.

### کاربران — زیرمجموعه‌ی یک ورودی
صفحه‌ی کاربران مثل «مدیریت کاربران» پنل Vodiwalker کار می‌کند: یک ورودی را انتخاب کنید، مشخصاتش را
ببینید (آدرس، مسیر، لینک ساب، «بازکردن صفحه‌ی ساب») و کاربرهای همان ورودی را مدیریت کنید — افزودن،
فعال/غیرفعال، کپی کانفیگ یا ساب، تولید UUID جدید، ریست مصرف، حذف. حجم، انقضا، سقف IP و اتصال در
لحظه‌ی اتصال چک می‌شوند.

### گزارش‌ها
هر ورود، **مدیر و آی‌پی مبدأ** را ثبت می‌کند (پشت پروکسی Railway، آی‌پی واقعی از `X-Forwarded-For`
خوانده می‌شود). تغییرات ورودی/کاربر/تنظیمات/مدیرها هم ثبت می‌شوند.

### تنظیمات — برای هر مدیر جداگانه
* **ظاهر** — زبان، تم، سبک رابط، موسیقی و صدا. این‌ها روی **حساب همان مدیر** ذخیره می‌شود؛ پس دو مدیر
  می‌توانند زبان و تم متفاوت داشته باشند و تغییرات هیچ‌کدام برای دیگری دیده نمی‌شود.
* **حساب من** — تغییر رمز خودتان.
* **پنل** (نام پنل، آدرس عمومی، پورت پیش‌فرض) و **پل Xray** — **فقط مالک**. مدیر عادی به‌جای فیلدها
  پیام می‌بیند و API کد `403` می‌دهد.
* **مدیران** (فقط مالک) — ساخت/غیرفعال‌سازی/حذف مدیر؛ آخرین مالک هرگز حذف نمی‌شود.

### صفحه‌ی گرافیکی سابسکریپشن (برای هر ورودی)
بازکردن لینک سابسکریپشن یک ورودی در مرورگر، صفحه‌ی اختصاصی همان ورودی را نشان می‌دهد — با تم انتخابی
شما، RTL در حالت فارسی — شامل:

* نشان‌های مشخصات ورودی (پروتکل/ترنسپورت/امنیت) و اندپوینت،
* **دونات مصرف** و اعداد آن،
* **کد QR** واقعی (SVG که در سرور ساخته می‌شود) برای لینک سابسکریپشن،
* دکمه‌های کپی برای لینک عمومی/کلش/سینگ‌باکس،
* یک کارت برای هر کاربر (وضعیت، نوار مصرف، انقضا) با کانفیگ‌های همان کاربر و دکمه‌ی کپی.

`/sub/<token>` برای ایمپورت در کلاینت و `/info/<token>` همین صفحه است؛ توکن کاربر فقط همان کاربر را
نشان می‌دهد و توکن ورودی، نود خود ورودی را در بالای همه‌ی کاربران.

### چه چیزی بومی سرو نمی‌شود
VLESS-WS و Trojan-WS توسط همین اپ سرو می‌شوند. اما **VMess، Shadowsocks، Reality و UDP** نه — پنل
لینک‌هایشان و بسته‌ی آماده‌ی پل Xray را می‌سازد (**تنظیمات → پل Xray → ساخت بسته**: `config.json` +
Caddyfile + مراحل).

## ۳. دیپلوی روی Railway

```bash
npm i -g @railway/cli
railway login
cd dollax-railway
railway init
railway up
```

سپس در داشبورد Railway:

۱. **Volume** با مسیر **`/data`** (تا `dollax.db` بین دیپلوی‌ها بماند).
۲. **Variables**:
   ```
   ADMIN_USERNAME=dollax26
   ADMIN_PASSWORD=یک-رمز…یک-کنید
   SECRET_KEY=یک-رشت…کت‌تری
   PUBLIC_BASE_URL=https://دامنه-شما
   DATA_DIR=/data
   ```
۳. **Settings → Networking → Generate Domain** (TLS خودکار است).
۴. آدرس `https://دامنه-شما/health` باید `{"ok":true,...}` بدهد.
۵. در `/login` با `dollax26 / dollax26` وارد شوید و بعد در **تنظیمات → حساب من** رمز را عوض کنید.

### اجرای محلی

```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000     # ورود: dollax26 / dollax26
```

## ۵. کیفیت پوشش‌داده‌شده

* **ریسپانسیو** — گریدها در ۱۰۸۰/۷۸۰/۵۶۰ پیکسل جمع می‌شوند، سایدبار و جدول‌ها اسکرول می‌خورند، بیلدر

* **راست‌چین** — با انتخاب فارسی کل پوسته (شامل حاشیه‌ی سایدبار و نوتیس‌ها) برمی‌گردد (`dir="rtl"`).
* **حالت‌ها** — حالت خالی برای همه‌ی لیست‌ها، اسپینر بارگذاری برای عیب‌یابی/گزارش‌ها، توست خطا برای هر
  درخواست ناموفق، و استایل hover/active/disabled روی همه‌ی دکمه‌ها.
* **اعتبارسنجی** — نام ورودی الزامی، مسیر نرمال‌سازی می‌شود (شروع با `/`، بدون فاصله/`?`/`#`)، مسیر
  تکراری → 409، پورت محدود ۱ تا ۶۵۵۳۵ و اعداد سقف‌دار.
* **دسترس‌پذیری/کیبورد** — `Esc` مودال را می‌بندد، فوکوس با رنگ تأکید مشخص است، همه‌ی کنترل‌ها
  `<button>` واقعی با برچسب هستند و `prefers-reduced-motion` رعایت می‌شود.
* **امنیت** — هش رمز با scrypt، کوکی سشن امضاشده، گارد نقش‌ها در API (`403` برای غیرمالک) و بررسی
  سهمیه/انقضا پیش از باز شدن تونل.

## ۶. اعتبارسنجی انجام‌شده

* `python -m py_compile` روی همه‌ی ماژول‌ها و `node --check static/app.js` — بدون خطا.
* **۶۷ از ۶۷** تست سرتاسری در حافظه (ورود، CRUD ورودی/کاربر، سابسکریپشن base64/کلش/سینگ‌باکس، رله‌ی
  واقعی VLESS و Trojan روی سرور echo، شمارش حجم، رله‌ی ورودی بدون کاربر، رندر صفحه‌ی گرافیکی،
  تنظیمات جدا برای هر مدیر، جداسازی نقش‌ها و محافظت از آخرین مالک).
* **۳۳ از ۳۳** تست زنده روی سرور `uvicorn` در حال اجرا (سلامت، ورود، لینک خود ورودی، وجود دونات و QR
  و دکمه‌های کپی در صفحه‌ی ساب، `/sub` بدون کاربر، کلش، ثبت آی‌پی ورود، ماندگاری تنظیمات، مدیر دوم با
  تنظیمات خالی خودش و `403` روی تنظیمات پنل، سرو شدن فایل موسیقی).

این اسکریپت‌ها در نسخه‌ی نهایی (فقط فایل‌های لازم Railway) حذف شده‌اند؛ دستورهای بالا همان نتیجه را
بازتولید می‌کنند.

## ۸. اگر دیپلوی کرش می‌کند

اپ قبل از سرو کردن، اطلاعات راه‌اندازی را در لاگ چاپ می‌کند — اول همان‌ها را ببینید
(Railway → سرویس شما → **Deployments → View Logs** یا دستور `railway logs`):

```
[dollax] data dir: /data
[dollax] Dollax Panel 2026.09.19-r1 starting on 0.0.0.0:8080
[dollax] SECRET_KEY from env: yes
[dollax] owner seed: dollax26 / env password
```

| لاگ / نشانه | علت | راه‌حل |
|---|---|---|
| `can't open file 'main.py'` یا module پیدا نشد | کل پوشه آپلود نشده | پوشه را کامل دیپلوی کنید، نه فایل‌های تک‌تک |
| کانتینر بلافاصله بعد از استارت خارج می‌شود | دستور استارت چیز دیگری اجرا می‌کند | `"startCommand": "python main.py"` در railway.json یا `CMD ["python","main.py"]` در Dockerfile |
| `data dir '/data' unusable (PermissionError…)` و بعد «TEMPORARY data dir» | `DATA_DIR=/data` بدون Volume | یک **Volume** روی `/data` بسازید یا `DATA_DIR` را بردارید |
| `Address already in use` | رپلیکای دوم یا پروسه‌ی قبلی پورت را گرفته | یک رپلیکا نگه دارید؛ اپ خودش به `$PORT` گوش می‌دهد |
| هلس‌چک Railway رد می‌شود ولی لاگ سالم است | اپ هنوز در حال نصب/بالا آمدن است | مهلت هلس‌چک در `railway.json` شصت ثانیه است؛ `/health` را دستی باز کنید |
| بعد از هر ری‌استارت همه از حساب خارج می‌شوند | `SECRET_KEY` خالی است | آن را تنظیم کنید (پایین) |
| `dollax26 / dollax26` رد می‌شود | رمز `ADMIN_PASSWORD` فرق دارد یا دیتابیس قدیمی است | مالک فقط **یک‌بار** ساخته می‌شود؛ قبل از اولین دیپلوی رمز را بگذارید یا `/data/dollax.db` را حذف و دوباره دیپلوی کنید |

### گرفتن SECRET_KEY

اختیاری است — اگر خالی باشد اپ در هر بوت یک مقدار تصادفی می‌سازد و فقط یعنی با هر ری‌استارت
لاگین‌ها پاک می‌شوند. هر رشته‌ی تصادفی بلند کار می‌کند:

```bash
python -c "import secrets;print(secrets.token_urlsafe(48))"
```
```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | % {[char]$_})
```
```bash
openssl rand -base64 48
```

پایتون ندارید؟ هر رشته‌ی تصادفی ۴۰+ کاراکتری از یک مدیریت رمز کافی است.
سپس: Railway → سرویس شما → **Variables** → **New Variable** → نام `SECRET_KEY`، مقدار را بچسبانید → **Deploy**.
(همان‌جا `ADMIN_PASSWORD` و `PUBLIC_BASE_URL` را هم بگذارید.)

## ۹. پنل روی چه پورتی اجرا می‌شود؟

**روی Railway پورت را شما انتخاب نمی‌کنید — خود Railway انتخاب می‌کند.** متغیر `PORT` را تزریق
می‌کند (طبق قرارداد ۸۰۸۰) و دامنه‌ی عمومی شما را به همان پورت می‌فرستد. اپ خودش `$PORT` را
می‌خواند، پس همیشه با هم هماهنگ‌اند:

```
python main.py                    # به 0.0.0.0:$PORT گوش می‌دهد و در نبود آن 8080
```

چک‌لیست:

۱. **Variables** — کاری لازم نیست؛ `PORT` تزریق می‌شود. (اگر شماره‌ی دیگری می‌خواهید، خودتان
   `PORT` را بگذارید، مثلاً `8080`.)
۲. **Settings → Networking → Public Networking** — دامنه‌ی ساخته‌شده یک **target port** دارد که باید
   برابر `$PORT` باشد (۸۰۸۰، مگر آنکه عوضش کرده باشید). اگر عدد اشتباه باشد، سایت
   «Application failed to respond» می‌دهد هرچند اپ سالم است.
۳. **هلس‌چک** — در `railway.json` روی همان پورت و مسیر `/health` تنظیم شده است.
۴. **اجرای محلی** — `python main.py` روی ۸۰۸۰، یا `PORT=3000 python main.py`، یا
   `uvicorn main:app --port 8000` (پیش‌فرض خود uvicorn). سپس `http://127.0.0.1:<port>` را باز کنید.

| مورد | پورت |
|---|---|
| پنل روی Railway | همان `$PORT` — پیش‌فرض **۸۰۸۰** |
| پنل محلی | ۸۰۸۰ با `python main.py` یا هر عددی که با `--port` بدهید |
| HTTPS عمومی | **۴۴۳** (لبه‌ی Railway کار TLS را انجام می‌دهد) |
| فیلد Port ورودی در بیلدر | **۴۴۳** — توضیح زیر |

### فیلد «پورت» ورودی، پورت شنود نیست

در **ورودی‌ها → Port** تعیین می‌کنید چه چیزی داخل لینک کلاینت بیاید
(`vless://…@دامنه:443`). Railway فقط **یک** پورت HTTPS عمومی می‌دهد، پس:

* برای همه‌ی ورودی‌ها **۴۴۳** (TLS) بگذارید؛ تفکیک آن‌ها با **مسیر** WebSocket است؛
* پورت‌های ۲۰۵۳ / ۲۰۸۳ / ۲۰۹۶ / ۸۴۴۳ فقط روی لبه‌ی Cloudflare (نسخه‌ی Worker) کار می‌کنند، نه اینجا؛
* تنها راه باز کردن پورت TCP اضافه در Railway قابلیت **TCP Proxy** است و این اپ روی پورت اضافه‌ای
  گوش نمی‌دهد — یک پروسه‌ی uvicorn، یک پورت، چند مسیر.

## ۱۰. آمار ترافیک و پینگ

**دانلود و آپلود حالا واقعی و برای هر کاربر جداست.** رله هر دو جهت را هنگام عبور ترافیک می‌شمارد:

* `upload` = کاربر → مقصد، `download` = مقصد → کاربر
* جدا ذخیره می‌شوند (`clients.up_bytes` / `clients.down_bytes`) و **در میانه‌ی اتصال** ذخیره می‌شوند،
  پس اگر اتصال قطع یا کشته شود، حجمی که رد شده از دست نمی‌رود
* در صفحه‌ی **کاربران** (ستون‌های اختصاصی ↓ دانلود و ↑ آپلود)، روی کارت ورودی‌ها، در صفحه‌ی گرافیکی
  سابسکریپشن و در هدر `Subscription-Userinfo` که کلاینت‌ها می‌خوانند، دیده می‌شود
* `used_bytes` همان مجموع است، پس محدودیت حجم درست کار می‌کند؛ دکمه‌ی **Reset** هر سه را صفر می‌کند

**پینگ** یک اندازه‌گیری TCP از سمت سرور است — همان مکانیزمی که Vodiwalker استفاده می‌کند
(`POST /api/network/tcp-ping`):

| کجا | کار |
|---|---|
| دکمه‌ی **Ping** در ردیف هر کاربر | ستون Ping همان ردیف را با میلی‌ثانیه پر می‌کند (یا `timeout`) |
| دکمه‌ی **Ping** روی کارت ورودی | آدرس:پورت خود آن ورودی را می‌سنجد |
| `POST /api/ping {host, port}` | عمومی؛ `{ok, latency_ms}` برمی‌گرداند |

این عدد تأخیر **سرور** تا مقصد است (آیا از پنل در دسترس است؟)، نه تأخیر گوشی شما.

فقط ترافیک VLESS/Trojan از این اپ عبور می‌کند؛ پس مصرف VMess/Shadowsocks تا وقتی از پل Xray رد شود
در این آمار دیده نمی‌شود.

### فرم افزودن ورودی حالا عمداً کوچک است

یک ردیف **انتخابگر (select)** — پروتکل (VLESS / VMess / Trojan / Shadowsocks) · ترنسپورت
(WebSocket / XHTTP / gRPC / TCP) · امنیت (TLS / Reality / None) · اثر انگشت — به‌همراه نام، آدرس،
پورت، مسیر، حجم، اعتبار (روز)، تعداد کانفیگ هر کاربر، سقف کاربر، یادداشت و کلید فعال/غیرفعال.
یعنی ۱۰ فیلد به‌جای بیش از ۲۰ فیلد.

حذف‌شده از رابط (اما هنوز در API پذیرفته می‌شود): **SNI**، **هدر Host**، ALPN، کلیدهای Reality،
سرویس/حالت gRPC، حالت XHTTP، نوع هدر TCP، flow، fragment و متد/رمز Shadowsocks. SNI و هدر Host
به‌صورت پیش‌فرض برابر آدرس ورودی می‌شوند که روی Railway همان چیزی است که می‌خواهید.

## ۱۱. ظاهر: فونت‌ها، پس‌زمینه‌ها و حریم خصوصی هر کاربر

همه‌ی گزینه‌های **تنظیمات → ظاهر** متعلق به همان مدیری است که وارد شده و تنها با زدن
**ذخیره‌ی ظاهر** ذخیره می‌شود — هنگام تغییر، پیش‌نمایش زنده را می‌بینید اما تا زمان ذخیره چیزی ثبت نمی‌شود.

| تنظیم | گزینه‌ها |
|---|---|
| زبان | English / فارسی (راست‌چین) |
| سبک رابط | ساده / شیشه‌ای |
| تم | ۷ تم |
| **فونت** | Inter · Vazirmatn · Poppins · Roboto · Space Grotesk · JetBrains Mono · System |
| موسیقی | روشن/خاموش + صدا |
| **پس‌زمینه** | رابط پیش‌فرض · سه پس‌زمینه‌ی آماده (*moon*، *minimal*، *arcade*) · **آپلود خودتان** |
| تیره‌کردن / محو | ۰–۸۰ درصد / ۰–۲۰ پیکسل |
| **استفاده از پس‌زمینه** | روشن/خاموش — خاموش کنید تا به رابط پیش‌فرض برگردد |

**تصویر آپلودی فقط برای خود مدیر دیده می‌شود.** تصویر بر اساس نام کاربری ذخیره می‌شود
(`admin_assets`) و تنها از طریق `GET /api/me/background` به خودش داده می‌شود؛ مدیر دیگر کد `204` می‌گیرد.
مرورگر تصویر را پیش از آپلود تا ۱۹۲۰ پیکسل کوچک می‌کند، سرور فقط JPEG/PNG/WebP می‌پذیرد و
بیش از ۳ مگابایت را رد می‌کند. دکمه‌ی **حذف پس‌زمینه‌ی من** آن را پاک می‌کند و به رابط پیش‌فرض برمی‌گردد.

پس‌زمینه‌های آماده در `static/bg/` هستند — هر فایل `*.jpg` دیگری آنجا بگذارید، خودبه‌خود
در انتخابگر طاهر می‌شود (`GET /api/backgrounds`).

**حذف‌شده در این دور**

* فیلد **نام پنل** در تنظیمات (مقدار ذخیره‌شده هنوز برای عنوان صفحات استفاده می‌شود)؛
* دکمه‌های سابسکریپشن در صفحه‌ی ورودی‌ها — لینک ساب هر کاربر در بخش **کاربران** است و صفحه‌ی
  گرافیکی هر ورودی همان جای قدیمی در `/sub/<token>` در دسترس است.
